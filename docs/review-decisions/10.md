# Review decisions of pull request #10 (vertical 1a: constater)

## R-10-1 | security | medium | fixed

- **Finding**: the `X-Adria-Mo` check compares the path case-sensitively, so `POST /API/v1/...` reaches the endpoints unchecked.
- **Where**: `src/AdriaMo.Api/Security/AppHeaderMiddleware.cs`.
- **Reason**: every request that changes something now needs the header, whatever its path; tests with `/API/...`, `/Api/V1/...` and an unknown path.

## R-10-2 | security | medium | fixed

- **Finding**: only the file size is limited; a small file can claim a huge image and exhaust the memory of the back end.
- **Where**: `src/AdriaMo.Api/Photos/PhotoIntake.cs`.
- **Reason**: the size in the header is read before decoding and over 64 million pixels is refused (`TooManyPixels`); a JPEG is decoded at the smallest scale that still gives twice the published size; two decodes at most at once. Test with a forged PNG of 10,000 × 10,000.

## R-10-3 | security | low | fixed

- **Finding**: a locked account answers faster than an unknown one, which tells that it exists.
- **Where**: `src/AdriaMo.Api/Accounts/AccountEndpoints.cs`.
- **Reason**: a locked account now hashes the decoy too. Locking the super-admin out by failing on purpose stays possible for 15 minutes at a time, limited per address; accepted for a building's tool (the alternative, no lockout for one account, is worse).

## R-10-4 | security | low | fixed

- **Finding**: an upload refused as a duplicate still writes its original.
- **Where**: `src/AdriaMo.Api/Constats/ConstatEndpoints.cs`.
- **Reason**: the duplicate is checked on the hash before anything is written. Files of a failure in the middle of an intake are named by their content and reused by the next identical upload; no clean-up job for now.

## R-10-5 | security | low | fixed

- **Finding**: the sandbox containers are not hardened.
- **Where**: `deploy/sandbox/compose.yaml`.
- **Reason**: read-only root file system, all capabilities dropped, `no-new-privileges`, a `tmpfs` for `/tmp`; the full e2e chain passes with it.

## R-10-6 | quality, architecture | major | fixed

- **Finding**: an exception the publisher does not expect (`SqliteException`) stops the whole back end; a failed publication is invisible and never retried; the daily publication is missing; one missing photo file blocks every publication.
- **Where**: `src/AdriaMo.Api/Publishing/SnapshotPublisher.cs`.
- **Reason**: every failure but a shutdown is caught (suppression justified); it is recorded in `PublicationStatus`, shown in the administration (`GET /api/v1/publication`, a banner above the constats) and retried after 1 minute, then twice as long, up to 30 minutes; a publication happens at least once a day; a photo whose files are missing is left out of the snapshot, its piece stays. Tests on a simulated clock: the gathering delay, a failure that keeps the previous snapshot and its retry, a missing file.

## R-10-7 | quality | major | fixed

- **Finding**: the result of `AddToRoleAsync` is ignored; a reset makes several writes and can leave a temporary password not flagged temporary.
- **Where**: `src/AdriaMo.Api/Accounts/UserEndpoints.cs`.
- **Reason**: an account that cannot get its role is deleted and the answer is an error; a reset checks the rules first, sets the flag and the unlocking before the reset, which saves them with the new hash.

## R-10-8 | architecture | major | fixed

- **Finding**: the admin calls the API same-origin only, while the spec put the API on another sub-domain: the production layout could not work.
- **Where**: `docs/spec.md` §10.3, §12.
- **Reason**: decided: the administration and its API share one address (the tunnel routes `/api/`, as the sandbox's static server does). No CORS, the cookie and the header work as they are.

- **Where**: `SnapshotPublisher`.
- **Reason**: the production vertical (6) brings R2 and the `IPublishTarget` it needs, with the ordering tested against a fake; designing the interface without its second implementation would guess its shape.

## R-10-17 | test | remove, merge | declined

- **Finding**: delete the null-argument and constant tests, merge the single-character tests, drop the hash-format parsing, the probabilistic passphrase test, and lower the iterations in tests.
- **Where**: `src/AdriaMo.Core.Test`, `src/AdriaMo.Api.Test/AccountTests.cs`, `web/src/lib/passphrase.test.ts`.
- **Reason**: the guards and the pinned role order are contracts the mutation tests rely on; the stored hash format is what spec §2.1 promises (PBKDF2-SHA512, 210,000 iterations, a salt), so reading it is the test of that promise; the suite runs in seconds at the production cost.
